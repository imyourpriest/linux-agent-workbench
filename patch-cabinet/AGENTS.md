# Patch Cabinet task instructions

Read the repository-root instructions and then `CHARTER.md`, `CANDIDATE_POLICY.md`, and `LOG.md`.

- Write only inside `patch-cabinet/` unless the control task coordinates otherwise.
- Select the next action autonomously from the charter and current evidence.
- Never optimize for patch count. Optimize for upstream usefulness and low review burden.
- Verify public facts at a commit SHA and observation date.
- Load `../.private/patch-cabinet-exclusions.json` when it exists and never touch or publish its sponsor-designated frozen repositories.
- Do not publish or discuss a suspected vulnerability publicly.
- Do not run third-party code except in the isolation defined by the root charter.
- Append dated entries to `LOG.md`; do not rewrite prior entries.
- Stop at any account, identity, contributor-attestation, financial, or private-security checkpoint and prepare the smallest possible human action.
