# Usage ledger

This is an allocation ledger, not a claim of exact token accounting.

Official product behavior makes exact consumption task-dependent: model, context, reasoning, tool
use, retrieval, and caching all affect usage. The agent can read the signed-in product Usage page
during an active turn when browser access is available, but cannot monitor it continuously or
attribute whole-account usage to one project. Sponsor reports remain valid snapshots. A work unit records
one bounded, substantive outcome and maintains the requested 2:1 ratio while both workstreams are
active; it does not equal a fixed number of messages, tokens, or credits.

## Policy

- Within the observed-start-to-40% envelope, schedule two impact work units for each revenue work
  unit while both projects remain active; do not infer fixed percentage-point costs per unit.
- Operational stop: 40% remaining. This leaves a 15-point uncertainty/overrun buffer above the
  sponsor's protected final 25%.
- Start no long or multi-agent work unit below 50% remaining.
- Scheduling ratio: two Patch Cabinet work units for each active revenue-workstream unit over a
  reset period.
- Shared governance work is allocated 2/3 to impact work and 1/3 to the active revenue workstream.
- Read the signed-in Usage page before and after each substantive work unit when available. Stop on
  a 40% or lower reading, any limit warning, or a lower sponsor report.
- The sponsor reports resets; browser observations are recorded only when directly visible.
