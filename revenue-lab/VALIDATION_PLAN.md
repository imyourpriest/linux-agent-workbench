# Validation plan

## Hypotheses

1. Commercial open-source maintainers have release friction that a bounded external repair can remove.
2. Exact evidence plus a passing patch is more valuable than another aggregate repository score.
3. Public samples and opt-in submissions can acquire qualified leads without cold outreach or platform spam.

## Phase 0 — Build proof

Exit criteria:

- trusted-local demo checker covers the initial evidence set, invokes no network client or subprocess, and cannot emit verified provenance;
- tests demonstrate deterministic output, file/symlink limits, and no code execution;
- one clearly synthetic demo report exists;
- offer, limitations, privacy, and refund drafts exist;
- public-source launch gate passes.

## Phase 1 — Ten samples

- Before any real repository sample, build and independently test the D-014 disposable acquisition environment. It must obtain and prove the upstream commit without local-object reuse or target-controlled Git metadata, then disable network access for analysis.
- Before that gate passes, do not feed third-party checkouts to the demo collector. Use only the synthetic fixture and source-linked, non-identifying educational pattern briefs derived from ordinary public web research.
- Select ten intentionally public Go/Python Linux CLI repositories with different release setups through maintainer opt-in, or analyze them privately and publish only non-identifying transferable patterns.
- After the acquisition gate exists, record the project-verified upstream commit and collector-derived observation date. Until then, publish only clearly synthetic reports or non-identifying pattern briefs.
- Publish named examples only with affirmative permission; otherwise publish anonymized pattern briefs that cannot reasonably identify the repository.
- Do not imply maintainer endorsement or contact maintainers through unsolicited issues/PRs.
- Invite opt-in submissions through the project-owned repository discussion/form once available.

## Phase 2 — Demand gate

Measure qualified page views as visits to an offer or sample page from an identifiable relevant channel. Do not claim that page views are unique people. Before measurement begins, publish a short privacy notice and configure the host for aggregate counts only: no project cookies, fingerprinting, session replay, advertising pixels, or collection of names, email addresses, raw IP addresses, or full user-agent strings for analytics. Retain campaign/referrer aggregates for at most 90 days; keep provider security logs only for the provider's shortest practical period and never publish raw logs.

Required before buying a domain or paid infrastructure:

- 10 published opt-in named examples or non-identifying pattern briefs;
- 100 qualified page views from relevant channels;
- 5 maintainer opt-ins;
- 1 explicit nonbinding request for a paid pilot through a form labeled “No order or payment is being taken.” The form requests only a public repository URL and a reply route, requires affirmative contact consent, and never collects payment data.

If the gate fails, pivot before spending.

## Phase 3 — First sale

Before payment:

- pass the D-014 acquisition and isolated-analysis gate for any real repository report or review;
- verify owner jurisdiction, trade-name/entity, tax, privacy, and bookkeeping requirements;
- establish a user-owned merchant account and MFA;
- publish exact scope, exclusions, delivery, revision, cancellation/refund, privacy/retention, and contact terms;
- test checkout, refund, delivery, and deletion flows;
- record customer consent for public case-study use separately from the service purchase.

## Initial acquisition channels

- project README and free reports;
- opt-in repository submissions;
- genuinely useful educational posts in channels that permit self-promotion;
- accepted Patch Cabinet work as evidence of process, never as a disguised sales pitch;
- later, a project-owned mailing list with affirmative opt-in.

Rejected channels: scraped email, bulk DMs, promotional GitHub issues, automated PRs, paid ads before conversion evidence, fake reviews, giveaways for engagement, or crypto incentives.
