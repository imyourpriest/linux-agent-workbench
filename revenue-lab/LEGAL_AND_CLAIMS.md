# Legal and claims boundary

This is an operating checklist, not legal or tax advice.

## Permitted description

Linux Release Readiness Lab provides provenance-labeled maintenance evidence and, when separately agreed, a bounded release-engineering patch for a public repository.

## Never claim

- “secure,” “vulnerability-free,” “compliant,” “certified,” or “production ready” based on this report;
- guaranteed acceptance, release success, sales, uptime, package availability, or future compatibility;
- maintainer endorsement without explicit permission;
- charitable donation status;
- customer counts, revenue, testimonials, or performance not supported by records.

## Required report disclaimer

> This report is a static maintenance-readiness observation with the provenance status shown in the report. Caller-supplied metadata does not establish repository or commit identity. The collector reads only the supplied trusted-local directory and invokes no network client, subprocess, Git command, or target code. It does not test deployed services or constitute a security audit, penetration test, certification, legal opinion, or guarantee. Findings may be incomplete or become stale.

## Before first payment

Any real repository report or review requires the independently tested D-014 disposable acquisition and network-disabled analysis environment. The trusted-local demo collector is not used on customer or third-party checkouts.

The human owner must verify applicable jurisdiction, trade-name/entity, consumer-protection, tax, sales-tax, privacy, breach, merchant, export, and bookkeeping obligations. A qualified professional is required when the answer is not clear from authoritative sources.

The checkout must identify the human-owned seller, exact deliverable, price, timing, revision allowance, exclusions, cancellation/refund rules, privacy/retention behavior, and support contact.

## Data boundary

- Public repository URLs and intentionally public metadata only at launch.
- No private code upload, access tokens, customer credentials, production data, or remote execution.
- Keep customer identity, payment, tax, and correspondence records outside the public repository.
- Public case studies require separate affirmative permission and must omit unnecessary personal data. Revocation stops future first-party promotional use where practical but cannot erase public Git history, forks, caches, archives, or third-party copies.
