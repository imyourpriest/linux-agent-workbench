# Linux Release Readiness Lab task instructions

Read the repository-root instructions and then `CHARTER.md`, `VALIDATION_PLAN.md`, `LEGAL_AND_CLAIMS.md`, `REVENUE_LEDGER.md`, and `LOG.md`.

- Write only inside `revenue-lab/` unless the control task coordinates otherwise.
- Select the next evidence-producing action autonomously.
- Do not build SaaS, buy a domain, or create paid infrastructure before the validation gates justify it.
- Analyze public repositories only. Never request or accept private source at launch.
- Do not run customer or third-party code. The MVP invokes no network client or subprocess, but its trusted-local demo path does not prove storage is offline.
- Do not feed a third-party checkout to the demo collector. Real acquisition waits for the reviewed disposable environment in D-014.
- Do not call the output a security audit, compliance review, certification, or guarantee.
- No cold-email automation, scraped contacts, promotional GitHub issues, fake engagement, or uninvited PR campaigns.
- Record prices as offers under test, not established market value.
- Append dated actions and outcomes to `LOG.md` and financial events to `REVENUE_LEDGER.md`; never fabricate a lead, visitor, order, or receipt.
- Stop at account, identity, merchant, tax, contract, payment, private-data, or purchase checkpoints and prepare the smallest possible human action.
